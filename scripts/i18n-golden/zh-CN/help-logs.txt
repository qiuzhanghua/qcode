Show where the log file is, and its most recent lines (ADR-0077)

Usage: qc logs [OPTIONS]

Options:
      --data-dir <DATA_DIR>
          Data directory. Defaults to the XDG data home

      --path-only
          Print the path and the file listing, but no log lines

      --config <CONFIG>
          Config file. Defaults to ~/.config/qcode/config.toml

  -n, --lines <N>
          How many trailing lines to show
          
          [default: 40]

      --approval-policy <PATH>
          Approval policy file ([[rules]]). Replaces the config's approval rules

  -f, --follow
          Keep printing new lines as they are written (Ctrl-C to stop)

      --grep <PATTERN>
          Show only lines matching this regular expression.
          
          A regex and not a substring: the useful patterns here are anchored classes (`session (starting|ending)`, `pid=14275`), and "it is a regex when it compiles as one" would make `session (` silently a substring search for a string nobody meant. An invalid pattern is an error, not a quiet fallback.
          
          The file's default level keeps third-party `info` out (ADR-0093), but a GUI start still writes its own hundred lines around the two lifecycle ones. Without a filter the only way to find "how did that run end" is `grep`, which is fine until the file is the thing you cannot read (a sandbox, a bug report from someone else). `--grep` makes it one command, and it applies to `--follow` too — which `grep` cannot do.

      --since <AGE|TIME>
          Drop lines older than this: a duration (`30m`, `2h`, `7d`, bare seconds) or an RFC 3339 timestamp

  -h, --help
          Print help (see a summary with '-h')
