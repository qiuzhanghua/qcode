# qcode icon set — "QC carve"

One glyph, four containers. The mark is a **QC monogram set on a diagonal**: the
pair descends like a slope, both letters lean 8°, and the C is drawn with a
calligraphic pressure stroke — thick where it carves, thin where it releases —
with three snow-spray dots at its exit. The Q's tail points into the turn.
Below 32 px the spray is dropped, the strokes thicken and the lean softens to 5°
so the two letters still survive as a silhouette.

Masters live in `src/`; everything else is generated by `./build-icons.sh` and
committed, so normal builds never need `rsvg-convert`.

## Files

| Path | Format | Use |
|---|---|---|
| `src/qcode-mark.svg` | SVG, monochrome, square artboard | optical master, 32 px and up |
| `src/qcode-mark-small.svg` | SVG, monochrome | optical master, 16–24 px (no spray, bolder) |
| `src/qcode-app.svg` | SVG, 1024 × 1024, colour | source for `.icns` / app `.ico` |
| `macos/qcodeTemplate.pdf` | PDF, black + alpha | menu-bar `NSStatusItem` image (vector) |
| `macos/qcodeTemplate.png` / `@2x.png` | PNG 16 / 32 | menu-bar image, non-vector path |
| `macos/qcode.icns` | ICNS 16–1024 | Dock / Finder app icon |
| `windows/qcode.ico` | ICO 16–256 | exe icon, taskbar (`WM_SETICON`) |
| `windows/qcode-tray.ico` | ICO 16–256, `#2F6BFF` | notification area (`NIF_ICON`) |
| `linux/hicolor/<size>/apps/qcode.png` | PNG 16–256 | icon theme lookup by `IconName="qcode"` |
| `linux/symbolic/apps/qcode-symbolic.svg` | SVG, monochrome | hosts that recolour `-symbolic` icons |
| `preview/qcode-icons-preview.png` | PNG | contact sheet |

## Why these formats

- **macOS menu bar** wants a *template* image: colour is ignored and only alpha
  is used, so the system can tint it for light/dark/accent. 16 pt with a 32 px
  `@2x` rep, drawn inside the 22 pt menu-bar working area. Always created on the
  main thread and assigned with `button.setImage` + `isTemplate = true`.
- **Windows** gets a DPI ladder, not one size: the tray is 16/20/24/32/40/48/64 px
  at 100–400 % scaling. All entries carry 32 bpp alpha; sizes are stored as
  PNG-compressed ICO entries (Vista+). Load them by DPI
  (`LoadIconMetric(..., LIM_SMALL, ...)` or `GetSystemMetricsForDpi`) rather than
  a fixed 16 px, and reload on `WM_DPICHANGED` / `WM_SETTINGCHANGE`.
- **Windows/Linux do not tint tray icons**, so the tray file ships brand blue
  `#2F6BFF`, which stays visible on both light and dark taskbars. If a
  monochrome look is preferred later, add a light variant and switch on
  `AppsUseLightTheme` (Windows) / the panel theme (Linux).
- **Linux** StatusNotifierItem looks icons up by theme name; either install the
  hicolor tree (packaging) or send `IconPixmap` as ARGB32 network-byte-order
  pixmaps. `qcode-symbolic` is picked up by shells that recolour symbolic icons.

## Wiring

- **macOS** — `crates/qcode-gui/src/tray.rs` embeds `macos/qcodeTemplate.pdf`
  with `include_bytes!`, builds an `NSImage`, marks it `isTemplate` and assigns
  it to the status-bar button at 18 pt. The Dock icon is copied into the bundle
  by `scripts/build-macos-app.sh` (`CFBundleIconFile=qcode.icns`).
- **Windows** — `crates/qcode/res/icon.rc` embeds the two ICOs as resources
  101 (app) and 102 (tray); the tray loads 102 at `SM_CXSMICON`, the window
  icon loads 101 at `SM_CXICON`/`SM_CXSMICON`.
- **Linux** — the 16/22/32/48 PNGs are embedded and decoded at startup into
  the SNI `IconPixmap` property (ARGB32, network byte order). `IconName` is
  intentionally empty so hosts use the pixmaps instead of a missing theme icon.
  The item registers as `org.kde.StatusNotifierItem-<pid>-1` and announces
  itself to `org.kde.StatusNotifierWatcher`, which is what actually makes a
  host show it. The right-click menu is a `com.canonical.dbusmenu` object at
  `/MenuBar` (show/hide toggle + quit), exposed through the SNI `Menu` property.

## Regenerating

```sh
cd crates/qcode/res/icons
./build-icons.sh        # needs rsvg-convert, python3, iconutil (macOS)
python3 preview/make-preview.py
```

`build/` holds throwaway intermediates and is git-ignored. `ico.py` is the ICO
container writer; `preview/make-preview.py` composes the contact sheet from the
same masters, so the preview can never drift from the shipped files.
